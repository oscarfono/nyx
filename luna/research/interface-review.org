#+AUTHOR: Cooper Oscarfono

* About this review

This review is about the interface of LUNA only.
The question is: how do voice-first assistants and ambient displays show
presence, take turns, stay fast and speak first?
The first review on 2026-11-20 covered 15 assistant projects.
That review kept only the feature backlog in =LUNA.org=.
This file keeps the notes.

** Method

The review used web searches on 2026-11-20.
Each finding names its source. Each source has one of these grades:

| Grade     | Meaning                                                  |
|-----------+----------------------------------------------------------|
| docs      | Official documentation or an official release post       |
| research  | A paper or a preprint                                    |
| guide     | A design guide from a large vendor or a research group   |
| anecdote  | A forum post or a blog post. One person, one setup.      |

*CAUTION:* The searches returned summaries of the pages, not the full
pages. Read a source before a design depends on it.

* Findings

** 1. One state machine, one presence element

All the projects show the state of the assistant with one element.

- Home Assistant Voice Preview Edition uses an LED ring. The ring shows
  listening, processing, responding and idle. Red shows an error or a
  muted microphone. The ring also counts down the last seconds of a
  timer. (docs, anecdote)
  - https://support.nabucasa.com/hc/en-us/articles/25764604971421-Status-colors-of-the-LEDs-status-LEDs-on-Home-Assistant-Voice-Preview-Edition
  - https://home-assistant.io/blog/2024/12/19/voice-chapter-8-assist-in-the-home
- LiveKit Agents UI has five audio visualizers. Each visualizer has a
  different behaviour for each state: connecting, listening, thinking and
  speaking. The live audio volume also moves the visualizer. (docs)
  - https://docs.livekit.io/frontends/agents-ui/audio-visualizer
  - https://livekit.com/blog/design-voice-ai-interfaces-with-agents-ui
- Open WebUI 0.12 shows an orb, or an animated 3D avatar (a VRM file).
  The avatar breathes, sways and blinks without custom animations. The
  mouth follows the loudness of the spoken answer. With the browser voice
  (Web API), the mouth does not move. (docs)
  - https://openwebui.com/blog/v0-12-0-a-voice-that-talks-back-and-a-face-to-go-with-it
  - https://openwebui.com/blog/v0-12-1-channel-apps-avatars-in-standard-calls
- OVOS (after Mycroft) shows an idle homescreen when nothing happens: an
  animated face or a clock, with the weather and the date. (docs)
  - https://openvoiceos.github.io/ovos-technical-manual/gui_service

*For LUNA:* Define one state machine in the core: =idle=, =listening=,
=thinking=, =working= (a tool runs), =speaking=, =error=. Each client
(the page, a future screen, the phone) draws the same states. The presence
element is one shape. The loudness of the TTS audio moves the shape. The
server sends the loudness, so the shape moves with Piper too. The idle
state is the ambient screen of finding 6.

** 2. Turn-taking and barge-in

- Pipecat stops the bot at once when the user speaks, and cancels the work
  in flight. Pipecat adds to the history only the part of the reply that
  the user heard. (docs)
  - https://docs.pipecat.ai/pipecat/fundamentals/interruptions
- Pipecat Smart Turn is a small model. It reads the audio after a pause
  and decides if the turn is complete. One talk gives 58.9% recall and
  68.4% precision for v3. (docs, anecdote)
  - https://ai.engineer/talks/designing-voice-agents-for-real-conversations
- LiveKit has an adaptive interruption model. The model tells a real
  interruption from a backchannel ("uh-huh"). A VAD-only mode stops on
  each sound. The default minimum speech for an interruption is 0.5 s.
  (docs)
  - https://docs.livekit.io/agents/logic/turns/adaptive-interruption-handling/
  - https://docs.livekit.io/agents/logic/turns/tuning/
- Open WebUI has the setting "Allow Voice Interruption in Call". (docs)
  - https://docs.openwebui.com/features/chat-conversations/chat-features/voice-mode

*For LUNA:* Start with push-to-talk. Push-to-talk needs no endpointing
model and makes no false turns. Let a press of the button stop LUNA at
once. Add voice barge-in later, with echo cancellation in the browser
(=getUserMedia= with =echoCancellation=). Copy the Pipecat rule: the
transcript keeps only the words that LUNA spoke before the interruption.

** 3. Latency

- Send each complete sentence of the model stream to TTS at once. One
  developer measured first audio from about 1100 ms down to about 250 ms.
  (anecdote)
  - https://dev.to/realmarcuschen/the-caller-heard-silence-for-two-seconds-before-the-agent-spoke-21m1
- Deepgram suggests a short first chunk, for example up to the first
  comma. Hermes Agent starts to speak after the first clause. (guide, docs)
  - https://developers.deepgram.com/docs/tts-text-chunking
  - https://hermes-agent.nousresearch.com/docs/zh-Hans/developer-guide/streaming-tts
- Piper makes audio for one full sentence at a time. Keep the model
  loaded. (docs)
- faster-whisper on a CPU: one forum post gives 2.3 s for a short command
  with =small-int8=, 3.3 s with =small=, 6.5 s with =medium-int8=. The
  Home Assistant add-on uses =base-int8= on amd64. (anecdote, docs)
  - https://community.home-assistant.io/t/run-whisper-on-external-server/567449
  - https://pypi.org/project/wyoming-faster-whisper/

*For LUNA:* Measure on luna (4 vCPU, no GPU) before a decision. Try
=base-int8= and =small-int8=. Speak the first clause at once. Answer the
fixed phrases in code (backlog #2), with no model call. Play an earcon
(finding 7) at once, so the silence before the reply has a meaning.

** 4. Follow-up without the wake word

- Gemini for Home listens for about 8 to 15 seconds after a reply.
  (docs)
  - https://support.google.com/googlenest/answer/7685981?hl=en-GB
- Home Assistant 2025.4 added continued conversation. The conversation
  agent must support it. Users of earlier versions made workarounds that
  listen for about 6 seconds. (anecdote)
  - https://community.home-assistant.io/t/what-is-continued-conversation-for-voice-assistant-pe/864058

*For LUNA:* When a reply ends with a question, keep the microphone open
for about 8 seconds. Show this in the presence element. At all other
times, close the microphone after the reply.

** 5. Wake word

- =openwakeword-wasm-browser= runs openWakeWord models in the browser with
  onnxruntime-web. The package is at version 0.1.1. (anecdote)
  - https://www.pkgstats.com/pkg:openwakeword-wasm-browser
- Deep Core Labs ported openWakeWord to the browser. A detection is valid
  only when the wake word model scores high and a VAD finds speech.
  (anecdote)
  - https://deepcorelabs.com/open-wake-word-on-the-web
- Picovoice Porcupine runs in the browser, offline. It is not open source.
  (docs)
- OpenClaw: a background recognizer listens for the trigger words. An
  overlay shows the partial transcript. The overlay sends after a silence.
  (docs)
  - https://docs.openclaw.ai/platforms/mac/voice-overlay

*For LUNA:* A wake word matters only for a screen that is always on. Run
the wake word in the browser, so no audio leaves the device before the
wake word. Ask for the wake word and the VAD together. Train a custom
"LUNA" model with the openWakeWord tools. Do not use a stock "hey jarvis"
model.

** 6. Glanceable and ambient display

- Calm technology (Weiser and Brown, 1995; Amber Case): use only some of
  the attention, and only when necessary. Put information in the
  periphery. Inform and calm. A small light can do more than a full
  screen. (guide)
  - https://oreilly.com/content/principles-calm-technology-we-are-not-bad-at-technology-technology-is-bad-at-us
  - https://en.wikipedia.org/wiki/Calm_technology
- Google Nest Hub shows the most important number from far away, for
  example the commute time. It shows more detail when a person comes near.
  Google tested text height, contrast and information density. (guide)
  - https://blog.google/products/google-nest/ultrasound-sensing
- The Nest Hub ambient mode is a clock or photos. The background blurs
  when an interaction starts. A "Your day" view has cards with key facts.
  (anecdote: press reports, 2019 and 2020)
  - https://9to5google.com/2020/10/27/hands-on-with-the-new-google-nest-hub-and-smart-display-ui-redesign-video/
- Open WebUI keeps the transcript in view in a side panel on a wide
  screen. On a phone, the call fills the screen. (docs)

*For LUNA:* The idle screen has three or four large facts that you can
read from across a room: the safe-to-spend number, days to the next swing,
the next bill, and the count of waiting approvals. Detail comes when you
touch or talk. When a conversation starts, the ambient screen goes to the
back and the presence element comes to the front. On a phone, the
conversation fills the screen.

** 7. Audio feedback (earcons)

- Google: an earcon is a short sound with one meaning. Use few sounds.
  Make each sound easy to tell from the others. Use them the same way each
  time, and not too often. If the user must learn a sound, do not use it.
  (guide)
  - https://developers.google.com/assistant/conversation-design/earcons
- NN/g: Siri plays a two-tone sound after the wake phrase. A sound only
  helps if the user knows its meaning. (guide)
  - https://www.nngroup.com/articles/audio-signifiers-voice-interaction/

*For LUNA:* Three earcons only: "I hear you" (listening starts), "I have
it" (the turn ends and LUNA starts to work), and "error". No sound for
"done": the voice of LUNA is the signal.

** 8. Speaking first (proactivity)

- Edwards and others studied how people interrupt a person in a complex
  task. People interrupted sooner when the matter was urgent. A natural
  break between two subtasks is the best time. An offer to postpone helps
  the person. (research)
  - https://arxiv.org/pdf/2106.02077
- One study gives nine principles for a proactive assistant: valuable,
  pertinent, competent, unobtrusive, transparent, controllable, deferent,
  anticipatory and safe. In a car, an assertive voice got more responses,
  but people found it less pleasant. (research)
  - https://arxiv.org/pdf/2405.07528
- "Inner Thoughts": the agent speaks only when its best thought is above a
  threshold. Otherwise it stays silent. (research)
  - https://arxiv.org/pdf/2501.00383

*For LUNA:* Most proactive items go to the display, not to the voice. LUNA
speaks first only for urgent items, or at a set time (the morning brief).
LUNA uses the roster: no speech during a shift at site, except urgent
items. Each spoken item has "later" as an answer. Keep a written rule for
what is urgent, in code, not in the prompt.

* What no project in this review does

No project in this review joins all of these: a character with a voice, a
living display, the plan and tool calls in view, and fixed money and
roster widgets. The parts exist. The whole is the design work for LUNA.
